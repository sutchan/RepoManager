让前端项目保持干净

面向前端、全栈开发者与多 Node.js 项目团队：7 项功能统一管理全局 node_modules 与项目缓存；危险操作执行前二次确认，支持预演模式与执行日志。

谁适合使用

面向需要同时维护多个前端项目的开发者与团队；单项目用户也能受益。

前端 / 全栈开发者

用一条命令启用全局依赖，不再为每个项目重复生成 node_modules。

多项目团队

统一清理仓库根目录下多个项目的缓存，按白名单执行，结果可追溯。

monorepo 维护者

可选递归扫描深层包目录，默认 3 层，避免误扫依赖与产物目录。

七项功能

功能编号与命令行参数一致，可直接调用。

01

启用全局 node_modules

配置 NODE_PATH 并清理项目内本地依赖。

02

重置 Node 配置

移除环境变量与项目 .npmrc。

03

清理 .next 缓存

写入同名文件以停止 Next.js 缓存写入。

04

恢复 Next.js 缓存

清除隐藏属性并删除占位文件。

05

安装全局依赖

分五组安装常用前端工具链。

06

清理所有项目缓存

按白名单清理缓存目录与本地依赖。

07

清理 Vite / 构建缓存

清理 .vite / .turbo / .angular 等目录。

演示

以下示例取自 CLI 契约；删除类操作请先在隔离目录预演。

桌面界面（GUI）

不带参数启动 repo-manager，选择仓库根目录，勾选预演后点击功能按钮 1–7；执行日志显示在结果区并写入 repo-manager.log。

命令行（CLI）

repo-manager                              # 启动 GUI
repo-manager -dry-run 1 ~/Github          # 预演功能 1（零副作用）
repo-manager 1 ~/Github                   # 确认后执行
repo-manager -lang en -recursive 7 ~/Github

路径按平台书写（Windows 如 E:\Github）；-dry-run 只输出计划操作，不修改文件。

删除不可逆。请先在隔离目录用 -dry-run 预演，确认后再执行。

三步开始

1

取得程序

从 Release 下载对应平台归档，或用 Go 构建 repo-manager。

2

选择目录

GUI 选择目录或 CLI 传入路径，config.ini 可保存默认目录。

3

执行功能

点击功能按钮 1–7，或用 repo-manager <1-7> [路径]。

技术栈

单一代码库交叉编译，平台差异收口到独立接口层。

Go 1.25+

产品本体编译为 Windows / macOS / Linux 单二进制，无第三方运行时依赖。

Fyne v2.8.2

桌面 GUI 使用单一 UI 依赖，配色遵循设计令牌；运行需要系统 OpenGL。

build tag 分层

nogui 标签仅编译 CLI；platform 接口按 build tag 隔离 Windows / Unix 实现。

原生 HTML / CSS / JS

本展示页无前端框架、无外部字体与图片请求；三语文案集中在一个脚本。

安全设计

  • 危险功能（1 / 6 / 7）执行前二次确认。
  • 预演模式只显示将执行的操作，不修改文件。
  • 递归扫描限制为 3 层（1–8 可配），自定义清理目录名经安全校验。
  • 执行日志同步写入可执行文件同目录的日志文件。

常见问题

是否需要联网或上传项目数据？

不需要。工具在本地运行，不上传仓库内容；联网仅发生在功能 5 安装全局依赖时。

支持哪些操作系统？

Go 版支持 Windows、macOS 与 Linux 单二进制；GUI 运行需要系统 OpenGL，纯命令行可用 nogui 构建。

界面语言可以切换吗？

支持简体中文、繁体中文与英文；CLI 帮助固定为英文，不随语言切换。
